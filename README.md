# ツギキキ ― 町の記憶を、次の担い手へ渡す聞き手AI

町の知識（祭りの段取りと、その理由）を、AIが声で聞き取り、「段取りメモ」や「暮らしの手引き」に整理して、次の担い手へ渡す仕組みです。

受け手のリクエストが次の聞き取りの質問を生む「循環」と、記録ではなく現場で使える形（段取りメモ）にして渡すことが、新しい点です。

チーム：ねぎたこ（個人枠チーム165）

**公開URL（デモ）**：https://tsugite-demo-698754785188.asia-northeast1.run.app/
（URLは2026年11月14日まで維持します）

※デモに登場する町・人物・語りは、すべて架空のものです。実在の地域の知識ではありません。実際の利用では、本人の同意を得た語りだけを、本人の確認を通して保存します。


## 最初にアクセスコードを入れてください（必須）

AIの利用は費用と誤用を防ぐため、チーム用のアクセスコードで保護しています。**コードを入れないとAIが動きません**。最初に、次の手順で入力してください。

1. 公開URLを開きます
2. 左上の「メニューを開く」ボタンで左メニューを開き、いちばん下の「設定」を押します
3. 「チームのデモアクセスコード」の欄に、コードを入れます
4. 「接続する」を押します。「接続を確認しました」と表示されれば準備完了です

**審査用のアクセスコード：`kataribekataribe`**（審査期間中のみ有効）

入力したコードは、このブラウザのタブを閉じるまで有効です。タブを閉じたら、もう一度入力してください。


## 各機能の触り方

### 見る側：行事の段取りを調べる
1. ホームの「行事の段取りを調べる」→「はじめる」
2. 町の名前の欄の下にある「架空の「青葉地区」で試す」を押します（**青葉地区は、デモのために用意した架空の地区です**。実在しません。押すと、あらかじめ入っている架空の語り手・田中はるさんの語りを根拠に、回答が返る状態になります）
3. 質問例のボタン（例：「準備の集合時間はいつごろですか？」「毎年何月くらいに準備をはじめるの？」）を押すか、自分で質問を入力します
4. 回答には出典の番号［1］が付きます。押すと、根拠になった語りや資料が開きます
5. 記録にない質問をすると「まだ記録がありません」と答えます。「この質問を地域の人に聞く」を押すと、語り部側の「届いている質問」に登録されます（例：「2019年に台風で中止したとき、誰がどう決めたの？」）

### 残す側：行事の段取りを残す
1. ホームの「行事の段取りを残す」→「はじめる」
2. 町の名前を入れるか、「架空の「青葉地区」で試す」を押します
3. 語り手の名前を入れ、「話して残す」を選びます
4. 聞き役のAIが一度に1つずつ質問します。答えは文字で入力するか（「架空の台詞を入力」で例文も入ります）、マイクで声で話します
5. 「手引きの下書きを作る」を押すと、集合時間・雨天の場所・用意するもの・作業の順番・その理由・確認先の6項目に整理されます。語られていない項目は「未確認」のまま残ります
6. 語り手本人が内容を見て、直して「確認して残す」を押したときだけ、「確認済み」になります。確認された手引きは、見る側の回答の根拠になります
7. 「資料を登録する」から、PDF・写真・動画も添えられます。

### 左メニュー
最近の質問（確認済みの手引き、聞き取り待ちの質問）が並びます。


## 仕組み

ブラウザの画面と、Cloud Run上の1つのサーバー（`server.mjs`）、Googleのサービスでできています。AIの呼び出しと保存は、すべてサーバーを通ります。APIキーはブラウザへ渡しません。

```
ブラウザ（画面・マイク・スピーカー）
   │  HTTPS（JSON） ／ WebSocket（音声）
   ▼
Cloud Run：server.mjs（アクセスコードと利用回数の確認、入力の守り）
   ├─ Gemini（Vertex AI）……質問の生成、手引きへの整理、出典つき回答
   ├─ Gemini Live（Vertex AI）……声の聞き取りと返答
   ├─ Firestore ……語り・手引き・確認状態、資料の説明
   └─ Cloud Storage ……資料ファイル
```

### 1. 聞き取り（語り部が話す）
1. 語り部が話す（声）か入力する（文字）。声のときは、ブラウザが音声を取り込み、WebSocketでサーバーへ送ります。サーバーがGemini Liveにつなぎ、返ってきた声をブラウザへ戻します。1回の会話は最大5分です
2. 語りは、1発言ごとに番号（ID）をつけて文字として残ります（生の音声は保存しません）
3. 文字のときは、サーバーがGeminiに「これまでの語り」を渡し、次の聞き返し質問を1つだけ作ります

### 2. 整理（手引きにする）
1. 「手引きの下書きを作る」で、サーバーがGeminiに語りを渡し、6項目（集合時間・雨天の場所・用意するもの・作業の順番・その理由・確認先）のJSONを作らせます
2. プログラムが、各項目の根拠の発言番号が、実在する語り手の発言か検査します。根拠のない項目は「未確認」に戻します
3. 語り手が画面で内容を確認して初めて、「確認済み」になります。この判定はAIではなく、プログラムと人の操作だけが行います
4. 確認済みの手引きは、Firestoreに保存されます

### 3. 調べる（受け手が質問する）
1. 受け手の質問に対して、サーバーが「確認済みの語り」と「登録された資料」を出典の候補として束ね、Geminiに渡します。Geminiには、検索や保存などの道具は渡しません
2. Geminiは、候補の中からだけ、出典番号（［1］など）つきで答えます。プログラムが、存在しない番号を取り除き、番号を振り直します
3. 根拠がなければ「まだ記録がありません」と答えます。「この質問を地域の人に聞く」を押すと、語り部の「届いている質問」に登録され、1に戻ります

### 資料の登録
PDF・写真・動画をアップロードすると、ファイル本体はCloud Storage、説明文はFirestoreに保存されます。動画は中身を見ず、入力したタイトルと説明だけを回答の根拠にします。

### 守り
アクセスコードと、作業領域ごとに1時間30回のAI利用制限をサーバーで確認します。語りや資料の中に混じった命令らしい文は、AIに渡す前に取り除きます（詳しくは「守りの設計」）。

## AIの役割の設計

AIは「答える役」ではなく「引き出す役」です。AIに「道具」（検索・保存・削除）は渡さず、保存と削除は、プログラムと人の操作だけが行います。「確認済み」と表示されるのは、語り手本人が画面で確認したときだけです。

聞き取り（聞き役）では、プロンプトで次の判断を固定しています。

・質問は一度に1つだけ

・場所・時間・手順・理由・確認先が曖昧なら、推測で進めず聞き返す

・推測で情報を追加しない。分からない項目は「未確認」にする（手引きの各項目は、根拠となる語り手の発言がない限り「未確認」のまま）

町の回答（見る側）では、次のとおりです。

・保存された語りと、登録された資料の中からだけ回答し、出典の番号を付ける（存在しない番号はプログラムが取り除く）

・記録が無ければ「まだ記録がありません」と答え、「この質問を地域の人に聞く」で次の聞き取りのテーマに登録できる


## 守りの設計（ガードレール）

・語り手・受け手の入力や、資料の文は、「命令ではなくデータ」として囲んで渡し、AIの役割の指示と分けています

・登録資料や語りの中に「AIへの命令」のような文が紛れていたら、AIに渡す前に取り除きます

・祭りや行事の段取り以外の依頼は、一文で断って本題に戻します。個人の連絡先は書かず、火・高所・重い物の作業は断定せず、現場の人への確認を促します

・AIの利用は、作業領域ごとに1時間30回までの制限とアクセスコードで守っています

・確認用の攻撃テスト（`scripts/attack-test.mjs`）で、命令の上書き・役割の乗っ取り・用途外・個人情報・記録に仕込んだ命令・記録のない質問への答え方を、公開URLに対して各3回ずつ確かめています


## 既知の制限

・実在の語り部による実使用の検証（実証）は未実施です。デモは架空データで、循環の成立までを確認した段階です

・Geminiによる生成と声の会話は、公開デモではチーム用コードで保護しています

・記録がない質問への応答はプロンプトと入力の整理で制御していますが、生成の揺れで関係する記録を提示する場合があります

・移住を考える人向けの流れは、拡張検討中の派生です。本命は担い手です

・方言や固有名詞の誤りがあり得ます。本人の確認ステップで正す設計です

・語り手の同意・公開範囲と削除、一般利用者の認証、記録の共有、費用のより強い制御は、実証前の残課題です。現状のデモは、実在人物の記憶を公開する用途には未完成です

## 開発者向け

### ローカルで動かす
Node.js 22以降が必要です。

```sh
npm ci
npm run build
npm test      # 自動テスト（42件）
npm start
```

表示された `http://127.0.0.1:4321` を開きます。キーがなければ、ルール処理の体験モードで動きます。

### 構成
- `public/`：画面、音声クライアント、画像、デモ用の初期データ（`seed.js`）
- `src/domain.mjs`：出典の検証、確認処理、体験モード
- `src/town.mjs`：町の出典つき回答の組み立て
- `src/guard.mjs`：守りの設計（命令とデータの分離、命令らしい文の除去）
- `src/materials.mjs`：資料（PDF・写真・動画）の保存。動画はタイトルと説明だけを根拠にします
- `server.mjs`：Gemini、Live用の短期トークン、Firestore／ローカル保存
- `scripts/`：ビルド、公開手順（`deploy-google.sh`）、攻撃テスト（`attack-test.mjs`）
- `tests/`：未確認情報、出典ID、確認必須、保存API、守りの設計のテスト

### 攻撃テスト
```sh
ACCESS_CODE=（デモのアクセスコード） node scripts/attack-test.mjs
```

### Google Cloudへ公開する
Cloud Shellで、`devfest165` を操作できるアカウントから次を実行します（Gemini APIキーとアクセスコードは、その場で非表示入力します）。

```sh
bash scripts/deploy-google.sh devfest165
```

Cloud Run（東京、サービス名 `tsugite-demo`、最小0・最大1インスタンス）、Firestore、Secret Managerを設定します。Liveの1回の会話は最大5分、AI APIは作業領域ごとに1時間30回の制限です。課金上限を保証する仕組みではないため、利用枠と課金状況を確認してください。

生の音声はこのアプリには保存しません。Liveでは会話の音声をGoogleへ送ります。APIキーはサーバーに置き、ブラウザへはLive用の短期トークンだけ返します。AIを使う前に、語り手の了解を得てください。
