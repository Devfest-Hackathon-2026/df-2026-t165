# ツギキキ フロントエンドの全体像（dev/front）

最終更新：2026-11-08　担当：Kazuya（フロント）

フロントは `dev/front` ブランチで、画面の流れが一通り動く状態です。この資料は、チームが**どんな画面があり、何がバックエンドとつながるのか**を一目で分かるようにまとめたものです。受け口の細かい入出力は [frontend-town-chat.md](./frontend-town-chat.md) にあります。

- 締切：コードフリーズ 11/10 17:00（Notionのルール）
- 対象ユーザー：その町に住んでいた人・いま住む人・これから住む人が、町の歴史を知る場面と、語り部が記録を残す場面
- サーバー側（`server.mjs`・`src/domain.mjs`・`public/live.js`）は変更していません。変えたのは `public/` の画面だけです

## 動かし方

```bash
git fetch origin
git checkout dev/front
git pull
npm ci          # 初回、または package.json が変わったときだけ
npm run build
npm start       # → http://127.0.0.1:4321
```

APIキーなしだと「体験モード」で動きます（AIの代わりに画面側のルール処理で答えます）。架空の「青葉地区」で一通り試せます。

## 画面の流れ

```mermaid
flowchart LR
  H[ホーム] -->|町の記録を見る| K{町は決まっている?}
  K -->|決まっている| P[町名を入力<br/>地図からも選べる] --> T[知りたいこと] --> C[町のチャット]
  K -->|決まっていない| Q[1問ずつ質問<br/>場所・大事なこと・方面] --> R[地域の候補] --> C
  H -->|町の記録を残す| P2[町名] --> W{残し方}
  W -->|話して残す| I[聞き取り] --> V[確かめて残す]
  W -->|資料を登録する| M[PDF・写真・カメラ]
  C -->|資料にない質問を<br/>地域の人に聞く| I
  V -. 確認済みの語りが根拠に .-> C
  M -. 登録資料が根拠に .-> C
```

町のチャットで答えられない質問は聞き取りのテーマになり、確認された語りや登録された資料は、次からチャットの根拠として使われます。この循環がツギキキの中心です。

## 画面ごとの説明

### ホーム

![ホーム](./images/01-hub.jpg)

- 「町の記録を見る」「町の記録を残す」の2択。最近見た町と、途中の聞き取り（続きから）も出ます
- 提灯の列と青海波の帯は飾り。`public/images/matsuri.jpg` を置くと、提灯の後ろに祭りの写真が入ります（フリー素材を募集中）

### はじめの質問（1問ずつ）

| 町が決まっているか | 画像タイルで選ぶ |
| --- | --- |
| ![町は決まっているか](./images/02-knows.jpg) | ![画像タイル](./images/03-tiles.jpg) |

- 上に進捗（例：4/6）と、これまでの答えを表示。下に「ひとつ前に戻る」「ホームに戻る」
- 選択肢はSpotifyの初期設定のような画像タイル。複数選べる質問は、選ぶと朱の枠とチェックが付きます
- どの質問にも自由入力の欄があります

### 地図で絞り込む

![地図](./images/04-map.jpg)

- 日本全国 → 地方 → 都道府県と、ピンか下のボタンで段々に絞り込みます（地図は国土地理院の淡色地図、Leaflet）
- 方面の質問と、町名の入力（「地図から選ぶ」）で使えます。市町村は入力してもらう形です

### 地域の候補

![地域の候補](./images/05-regions.jpg)

- 答えから候補を出し、「合う点」を表示。条件を書き足して探し直せます
- **今はキーワードでの簡単な振り分け（3地域固定）**です。バックエンドで判断できると良くなります

### 町のチャット（メイン画面）

| 町のチャット | 根拠を押したところ |
| --- | --- |
| ![町のチャット](./images/07-town-chat.jpg) | ![根拠](./images/08-citation.jpg) |

- AIが資料と確認済みの語りをもとに答えます。本文の番号と、回答の下の「根拠」の札は同じ資料を指し、押すと抜粋が開きます
- 資料で答えられない質問は推測で答えず、「この質問を地域の人に聞く」を出します（押すと聞き取りのテーマに）
- 右に「直接たずねる」（連絡先）と「この町の資料」。連絡先の登録がない町では、「町名＋図書館」などをGoogleマップで検索するリンクを出します（現在地ではありません）
- 知りたいことの選択肢（6枚目の画像）から入ると、その質問が自動で送られます

![知りたいこと](./images/06-topic.jpg)

### 記録を残す

| 残し方を選ぶ | 資料（PDF・写真）の登録 | カメラで撮る |
| --- | --- | --- |
| ![残し方](./images/09-record-how.jpg) | ![資料の登録](./images/10-materials.jpg) | ![カメラ](./images/11-camera.jpg) |

- 資料：PDF・JPEG・PNG・WebP（1ファイル20MBまで）。名前・年代・出どころ・説明・見られる人を入れ、「残してよいか確認しました」のチェックが必須
- カメラ：パソコンはブラウザ内で撮影、スマホは端末のカメラが起動。撮った写真は資料と同じ流れで登録。https（Cloud Run）かlocalhostでのみ動作
- 登録した資料はサーバーに保存され、町のページを見るほかの人にも見えます（`integrate/front-main`）。送れないときだけ端末のブラウザに保存します

| 話して残す（聞き取り） | 確かめて残す |
| --- | --- |
| ![聞き取り](./images/12-interview.jpg) | ![確認](./images/13-review.jpg) |

- 既存の聞き取り→手引きの下書き→語り手の確認の流れはそのまま。聞き取りの画面からも資料を添えられます

## バックエンドとのつながり

### 既存のAPI（変更なしでそのまま使っています）

| API | 呼ぶ画面 | AI未接続のとき |
| --- | --- | --- |
| `GET /api/config` | 起動時 | — |
| `GET/PUT /api/workspace/:id` | 起動時・保存のたび | ブラウザ保存のみ |
| `POST /api/followup` | 聞き取り | 画面側のルール処理 |
| `POST /api/card` | 聞き取り → 確かめて残す | 画面側のルール処理 |
| `POST /api/answer` | この記憶に聞く | 画面側のルール処理 |
| `POST /api/live-token` | 聞き取り（声の会話） | ボタンを出さない |

### 新しく必要なAPI

**`integrate/front-main` ブランチで5つとも実装済みです**（`main` の取り込みも済み）。入出力・保存先・残りの課題は [frontend-town-chat.md](./frontend-town-chat.md) を見てください。

| API | 優先 | 画面 | 役割 |
| --- | --- | --- | --- |
| `POST /api/town-answer` | 必須 | 町のチャット | 資料と語りを根拠にGeminiが答える。根拠の番号つき |
| `POST /api/materials` | 必須 | 資料の登録・カメラ | ファイルをCloud Storage、説明をFirestoreへ |
| `GET /api/materials?place=` | 必須 | 町のチャット | 町の資料一覧 |
| `GET /api/town?place=` | あれば | 町のチャット | 町の資料・連絡先・質問例 |
| `POST /api/regions` | あれば | 地域の候補 | 答えと自由入力から候補を出す |

受け口ができれば、画面は変更なしで切り替わります（失敗・未実装のときは体験用の回答に戻ります）。入出力の形は [frontend-town-chat.md](./frontend-town-chat.md) を見てください。

### データの置き場所

| データ | 今 | 統合後（案） |
| --- | --- | --- |
| 相談・聞き取りの記録（`state.requests`） | ブラウザ＋`PUT /api/workspace` | そのまま |
| 資料の説明（`request.materials`） | `/api/materials` で町ごとに保存 | Firestore（実装済み） |
| 資料のファイル本体 | サーバー（本番はCloud Storage）。送れないときだけブラウザ | Cloud Storage（実装済み） |
| 町のチャット履歴 | ブラウザ（localStorage）のみ | 必要ならFirestore |
| 町の資料・連絡先 | `public/town-data.js`（架空の青葉地区のみ） | `GET /api/town` |

## 統合で決めること（優先順）

1. **`dev/front` と `main` の統合**：`main` の安定化コミットが `dev/front` に入っていません。どちらも `public/app.js` を変えているので、フロント担当と一緒に統合します
2. **`/api/town-answer` の実装**
3. **資料ファイルの保存**（Cloud Storage＋`/api/materials`）
4. **手引きの6項目が提灯準備用に固定**：`src/domain.mjs` の `FACTS` が「雨天の場所」など。町の歴史の聞き取りでも出てしまう
5. **Gemini Liveの接続**：短期トークンが `v1beta` 指定だが、SDKの型定義ではv1alphaのみ対応。モデル名 `gemini-3.8-live` も要確認
6. 地域候補の振り分けをGeminiに（任意）

未解決の問い：

- [ ] 資料の「見られる人」を、デモでは区別なしで扱ってよいか
- [ ] 町のチャット履歴をサーバーに保存するか
- [ ] PDFの本文を回答の根拠に使うか（使うなら本文抽出が必要）
- [ ] 祭りの写真（フリー素材）を誰が探すか。クレジット表記が要るならフッターに入れます

## デザインの決めごと

| 項目 | 内容 |
| --- | --- |
| ロゴ | 木組みの継手（蟻継ぎ）。紺の部材＝語り手と町の過去、山吹の部材＝次の担い手（`public/logo.svg`） |
| 書体 | 見出し：Klee One（手書き風）、本文：Zen Maru Gothic（丸ゴシック） |
| 色 | 生成り（背景）、紺（主役）、朱（送信ボタン・提灯）、山吹（飾り・進捗）、浅葱（根拠・確認済み）、墨（文字）。和田三造『配色総鑑』の組み合わせを参考 |
| 文様 | 青海波（帯・ページ下端）、提灯の列（ホーム） |
| 動き | 提灯が揺れて灯りが明滅、波がゆっくり流れる、回答が浮かび上がる。動きを減らす設定では停止 |
| 配置 | 町のチャットは、チャット欄を一番大きく明るく。根拠は回答の下に1行の札。脇の欄は控えめ |
