# Google接続を確認する人へ

公開先のプロジェクトは **devfest165**。実行する人は、このプロジェクトの権限を持つ仲間です。

1. Cloud Shellでこのリポジトリを取得し、`bash scripts/deploy-google.sh devfest165` を実行する。
2. コマンド末尾に表示されたCloud RunのURLを開く。アプリの「設定」に、公開時に登録したデモアクセスコードを入力する。
3. Cloud Shellのアプリフォルダで、以下を実行する。`https://...run.app` は実際に表示されたURLに置き換える。

```sh
npm ci
read -r -s -p 'デモアクセスコード: ' TSUGITE_DEMO_ACCESS_CODE
echo
export TSUGITE_DEMO_ACCESS_CODE
node scripts/check-google.mjs https://...run.app
```

最初のチェックでは、起動、設定、アクセスコードによる保護、保存先を読む権限を確認します。実データは作成・変更しません。Firestoreの書き込み確認は、アプリから架空の話を保存したうえで、コンソールでも確認してください。

## 実AIも確認する

```sh
node scripts/check-google.mjs https://...run.app --ai --live-token
unset TSUGITE_DEMO_ACCESS_CODE
```

`--ai` は、架空の台詞を使ってGeminiへの聞き返しと手引き作成を各1回呼び出します。利用枠や料金を消費し得ます。`--live-token` は音声接続用の短期トークンの発行だけを確認し、トークン自体は画面に表示しません。

「OK」が出ても、**話の意味が正しく整理されていること・マイク入力・AIの音声応答は未確認**です。以下の手動確認が残ります。

## 最後に人が行う確認

- 架空の話で質問→聞き取り→下書き→確認保存→再読込を一周する。
- 元発言と手引きを照合する。雨の日と晴れの日、時刻、人名を取り違えていないか確かめる。
- 「声で会話を続ける」で音声を往復させる。会話終了と画面移動の両方で、ブラウザのマイク表示が消えることを確かめる。
- 回答のない質問を2件残し、それぞれのボタンが対応する質問を保存することを確かめる。
- Firestoreの `tsugite_workspaces` に保存されたことをコンソールで確かめる。
- 出力を撮影してから、料金と利用状況を確認する。

## エラーが出た場合

| 止まった場所 | 確認するところ |
|---|---|
| 起動 | Cloud Runのログ、PORT、Dockerのビルド結果 |
| アクセスコード | Secret Managerの `tsugite-access-code` と画面に入力したコード |
| 保存先の読み取り | FirestoreのDB名、実行用サービスアカウントの権限 |
| Gemini | APIキーの所属・利用枠・対象モデルへのアクセス、環境変数 |
| Live用トークン | Live APIへのアクセスとモデル名 |
| 音声だけ動かない | HTTPS、マイク許可、対応ブラウザ、実際のLiveモデルへのアクセス |

キーやアクセスコードをスクリーンショット・エラーログと一緒にチャットへ送らないでください。
