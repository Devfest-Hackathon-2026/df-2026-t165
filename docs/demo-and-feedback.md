# ツギテ：FB反映と3分デモ

## 今回反映したFB

- **記録側を設定の外へ**：左側に「話を残す」を独立表示。スマートフォンではメニューから入る。
- **地域を風景と位置で理解**：東北の里山・関西の町並み・瀬戸内の海辺のカードに風景、位置の説明、Google マップへの入口を付けた。画像はAI生成のイメージとして表示。実在の取材済みの町や人物とは区別する。
- **最初に大まかに絞る**：「海のそばで地元の暮らしを知りたい」などの入力で候補へ進み、関心を変えて選び直せる。現状はキーワードによる体験用の振り分け。
- **ボタンを少なく**：最初の画面は相談入力・音声入力・送信が中心。履歴は折りたたみ、検証や書き出しは設定内。

## ハッカソンで見せる芯

旅行案内の見た目だけでは競合との差が伝わりにくい。審査用の3分では、**若手の質問が次の聞き取りを生み、地域の経験が使える知識として残る循環**を主役にする。旅行者の入口は冒頭か最後に短く見せる。

| 時間 | 映像・操作 | 伝えること |
|---|---|---|
| 0:00–0:20 | 初担当の若手が「雨の日、提灯はどこで準備するの？」と困る | 知識が消えると、明日の準備が止まる |
| 0:20–0:40 | 「行事の引き継ぎについて相談する」から質問を作る | 聞くテーマは、使う側の疑問から生まれる |
| 0:40–1:20 | 「話を残す」。語り手が「いつもの場所」と答え、聞き役が建物名を聞き返す。理由と確認先も聞く | 録音するだけでなく、次の人に伝わる形まで聞く |
| 1:20–1:50 | 下書きの場所・理由・確認先と元発言を見せ、語り手が確認して残す | 出どころが分かり、分からないことを埋めない |
| 1:50–2:25 | 「この記憶に聞く」で「雨の日はどこ？」。確認済みの答えと根拠が表示される | 文章を保管するだけでなく、経験に質問できる |
| 2:25–2:45 | 「祭りの開催日は？」は未記録。「次の聞き取りへ」→「話を残す」でその質問が出る | 知らない質問が、次の記憶を集めるきっかけになる |
| 2:45–3:00 | 実際に測定した場合だけ、全文／手引きの時間・正答率を示す。未測定なら今後の検証として説明 | 効果を測る設計まで示す。作った数字は使わない |

### 体験モードでの操作

「行事の引き継ぎについて相談する」→ 質問入力 →「経験者に聞く」→「架空の台詞を入力」→送信を4回 →「手引きの下書きを作る」→内容確認 →チェック →「確認して残す」→「この記憶に聞く」。

「架空の台詞を入力」は撮影用の補助です。実AIが生成・判断した場面と混同させないでください。現在の公開プレビューは体験モードです。本番でGemini Liveを見せるには、Google版で実際の接続確認を済ませてから撮影します。

## 検証状況

- 自動テスト7件合格：欠落情報、元発言のID、確認必須、知識の質問、ローカル保存APIなど。
- ブラウザ確認：質問→聞き返し→下書き→確認修正→保存→再読込、元発言表示、既知／未知の質問、未知質問から次の聞き取り、地域の候補絞り込み。
- スマートフォン幅390pxで最初の画面を確認。
- 当事者による使いやすさ・社会的効果は未測定。音声認識・Gemini Live・Firestore・Cloud Runは認証後の実接続テストが必要。

## Google Cloudを持つ仲間に渡すもの

`ツギテ_実装一式.zip` と `ツギテ_Google公開の手順.md`。
プロジェクトIDは **devfest165**。Google Cloud ShellでZIPを展開し、アプリのフォルダで `bash scripts/deploy-google.sh devfest165` を実行する。APIキーはCloud Shellで非表示入力し、チャットに送らない。

Cloud RunのURLが出たら、アクセスコードを設定に入力し、Geminiでの聞き取り・確認保存・音声会話を実際に試す。プレビューURLはGoogleでの公開を満たすものとしては扱わない。
